# Bitwarden Component Library (Lit)

The Bitwarden Component Library (CL) is a collection of reusable low-level components that empower
designers and developers to work more efficiently. The primary goal is to ensure a consistent design
and behavior across the different clients and platforms.

`@bitwarden/components-lit` rebuilds the Angular library (`libs/components`) as framework-neutral
web components with [Lit](https://lit.dev). Every element works in plain HTML, Lit, Angular or any
other framework, and renders into its own shadow root. Feature parity with `libs/components` is the
goal: behavior directives (tooltips, menus, focus management, keyboard handling) are included, not
just visuals.

## Using the library

### 1. Load the document styles

Host pages must load `src/styles/document.css` once. It provides the theme custom properties, fonts,
and the icon font face (browsers ignore `@font-face` inside shadow roots), plus the `.bit-compact`
switch:

```ts
// Path relative to the repo root; use your bundler's CSS import.
import "libs/components-lit/src/styles/document.css";
```

Themes follow the `theme_light` / `theme_dark` class on an ancestor, usually `<html>`.

### 2. Configure the app once at startup

```ts
import { setAsyncActionErrorHandler, setTranslator } from "@bitwarden/components-lit";

// Components translate their built-in strings (`t("close")`, `t("loading")`, ...) with the
// app's messages, using the same keys as the Angular library.
setTranslator((key, ...params) => i18nService.t(key, ...params));

// Errors thrown by `action` / `submitAction` handlers land here instead of being rethrown,
// e.g. to show a toast, like Angular's `ValidationService` for `bitAction`.
setAsyncActionErrorHandler((error) => validationService.showError(error));
```

Optional: `setCopyClickClipboard()` / `setCopyClickToastHandler()` for copy-to-clipboard, and a
`<bit-toast-container>` at the app root to place toasts.

### 3. Import the elements

Importing a module registers its elements. Import the barrel to register everything, or individual
component modules to keep bundles small:

```ts
import "@bitwarden/components-lit"; // every element, plus functions and types

import "./button/button"; // inside this repo: just `bit-button`
```

Then use the tags anywhere:

```html
<bit-button button-type="primary">Save</bit-button> <bit-input label="Name" required></bit-input>
```

Keep side-effect imports (`import "./x"`) separate from type imports
(`import type { X } from "./x"`): a type-only import is elided, and the element never registers.

## Conventions

- **Files:** one folder per component family (`src/<name>/<name>.ts`, `<name>.stories.ts`,
  `index.ts`). Tags are `bit-<name>`, classes `Bit<Name>`.
- **Styling:** components extend `BitElement` and use `tw-` Tailwind classes in their templates.
  Class strings must be full literals; the shared sheet is generated by scanning this library's
  source.
- **Shadow DOM:** consumers' classes don't reach inside a component. Components expose layout knobs
  as CSS custom properties (`--bit-chip-max-width`, `--bit-compact`, ...) and `::part()`s instead of
  class-name inputs.
- **Attributes:** multi-word properties use kebab-case attributes (`button-type`, `start-icon`).
  Booleans default to `false`; variants are string-literal unions.
- **Events:** Angular outputs become `CustomEvent`s with the same name (`dismissed`,
  `selectedChange`), which bubble and cross shadow boundaries.
- **Accessibility:** interactive elements live in the shadow root, and components use
  `ElementInternals` for host semantics. Labels, hints and errors render inside each form control,
  so ARIA references always resolve.
- **Overlays:** menus, popovers, tooltips and dialogs use the top layer (`popover` / `<dialog>`).
  Content appended outside a component must go to `getOverlayRoot()`, or it is inert under a modal
  dialog.

## Differences from the Angular library

The API stays close to `libs/components` where that still makes sense: tag names, property names
(`buttonType`, `startIcon`, `variant`) and events carry over. It changes where a web-component
native API is better.

### Content and naming

- `ng-content` becomes `<slot>`; `select="[slot=end]"` becomes `<slot name="end">`.
- `title` inputs become `heading` on `bit-dialog`, `bit-popover`, `bit-callout`, `bit-banner`,
  `bit-accordion` and `bit-toast`, because `title` is a global HTML attribute that shows a native
  tooltip. `bit-header` keeps `title`.
- Angular's `bitTypography` attribute is the `bit-typography` element or the `typography(variant)`
  class helper; `bitLink` / `bitButton` on native elements become `bit-link` / `bit-button`.

### Directives become functions

Attribute directives become a framework-neutral `attachX(element, options)` function returning a
handle, a Lit element directive, and (where useful for plain HTML) a wrapper element or a
declarative attribute:

| Angular                                      | Lit                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `bitTooltip`                                 | `attachTooltip()`, `${tooltip(...)}`, `<bit-tooltip>`                                      |
| `[bitMenuTriggerFor]`                        | `attachMenuTrigger()`, `${menuTrigger(menu)}`, `<bit-menu trigger="id">`                   |
| `[bitPopoverTriggerFor]`                     | `attachPopoverTrigger()`, `${popoverTrigger(p)}`, `<bit-popover trigger="id">`             |
| `[bitPopoverAnchorFor]` + `popoverOpen`      | `attachPopoverAnchor()`, `${popoverAnchor(p, { open })}`, `<bit-popover anchor="id" open>` |
| `appCopyClick`                               | `attachCopyClick()`, `${copyClick(...)}`, `<bit-copy-click>`                               |
| `appA11yTitle`                               | `attachA11yTitle()`, `${a11yTitle(...)}`                                                   |
| `bitDialogClose`                             | `data-bit-dialog-close`, `${dialogClose(result)}`                                          |
| `bitMenuClose`                               | `data-bit-menu-close`                                                                      |
| `bitScrollLayoutHost`, `bitCollapseOnScroll` | `attachScrollLayoutHost()`, `collapseOnScroll()`                                           |
| `appAutofocus`                               | the native `autofocus` attribute                                                           |

### Services become functions

Angular services become plain module functions and state objects:

- `DialogService` → `openDialog(content, config)`, `openSimpleDialog(options)`, `openDrawer()`,
  `closeAllDialogs()`. Content is an element, tag name, Lit template or `(ref) => template`;
  `DialogRef.closed` is a promise.
- `ToastService` → `showToast({ variant, title, message })`.
- `PopoverService` / `SpotlightService` → `openPopover()` and the `spotlight` property.
- `SideNavService` → `SideNavState`, provided by `bit-layout`.
- `LayoutFooterService` / `ScrollLayoutService` → `layoutFooter`, `scrollLayout`.
- `I18nService` → `setTranslator()`; `CompactModeService` → the `.bit-compact` class and
  `--bit-compact` custom property (see Compact Mode).

### Routing

The library doesn't depend on a router. `route` / `routerLink` inputs become `href` plus an explicit
`active` / `current` property: the app decides what is active (`bit-nav-item`, `bit-tab-link`,
`bit-breadcrumb`, `bit-menu-item`). Components that read route data in Angular
(`bit-anon-layout-wrapper`) take it as a property.

### Forms

- Form controls are form-associated custom elements (`ElementInternals`): they take part in native
  `<form>` submission, validation, reset and `FormData` without Angular forms.
- `bit-form-field` + `bitInput` become self-contained fields (`bit-input`, `bit-select`,
  `bit-multi-select`, `bit-textarea`, ...) built on `BitFieldElement`, which renders the label, hint
  and error. `bitPrefix` / `bitSuffix` become the `start` / `end` slots. `bit-form-control` +
  `bitCheckbox` becomes `bit-checkbox`.
- Validators are native constraints (`required`, `min`, `maxlength`, ...) plus `Validators` from
  `src/core/validators.ts` via the `validators` property; error messages use the Angular i18n keys.
- `bitPasswordInputToggle` is the `password-toggle` attribute on `bit-input`.
- `[bitSubmit]` + `bitFormButton` become `submitAction(handler)` / `<bit-form>`; `bitAction` becomes
  an `action` property taking a promise-returning function.

### Styling

- Styles live in each shadow root, so host-page CSS doesn't leak in. Customize with the documented
  custom properties and parts.
- The `bit-compact:` variant is a style container query on `--bit-compact`, not a descendant
  selector, so it works across shadow boundaries.

### Feature flags

Components with a pre-VFO1 design take a `legacy` boolean (`bit-layout`, `bit-side-nav`, `bit-page`,
`bit-header`) instead of reading the `VFO1Foundation` flag from a service.

## Storybook Guide

Each component folder contains a documentation page (`*.mdx`) and story examples (`*.stories.ts`).
Stories cover every state the Angular stories cover, plus interaction demos for keyboard and open
states. Titles match `libs/components` (`Component Library/<Name>`), so the two Storybooks can be
compared side by side.

Please note that code snippets and examples may not be production-ready, i.e. they may be missing
required properties or container-level styling.

### When to add to Storybook

- A new component is added — Storybook representation is a requirement for all components
- A regression is identified for a usage that isn't represented yet
- More context would have helped you implement a component, or a docs page has an error

### How to add to Storybook

1. Add `<name>.stories.ts` (and `<name>.mdx` for usage docs) next to the component. Use
   `import type { Meta, StoryObj } from "@storybook/web-components-vite"` and
   `satisfies Meta<Args>`.
2. Cover the default case and variants, common patterns, and edge cases: long text, disabled and
   loading states, icons.
3. Use the real components in examples rather than stand-ins.
4. Prefer stories over unit tests; reserve tests for non-rendering logic.

### Running Storybook locally

From `libs/components-lit`, run `npm run storybook` (serves on port 6008).
