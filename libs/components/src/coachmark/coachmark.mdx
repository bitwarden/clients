# Coachmark

A coachmark tour walks the user through a few parts of the UI, one spotlit popover at a time. Each
step shows a title, a short description, an optional "Learn more" link, a "2 of 3" style indicator,
and Back / Next / Close.

<Primary />

## Usage

A tour has two parts:

- **`CoachmarkTourService`** holds the steps, their anchors, and which one is active. Provide it on
  the component that owns the tour, so each tour gets its own instance.
- **`<bit-coachmark>`** is one step's content. It shows while its step is active, spotlighting that
  step's anchor.

```ts
@Component({
  providers: [CoachmarkTourService],
  …
})
export class VaultComponent {
  private readonly tour = inject(CoachmarkTourService);
  private readonly toolbar = viewChild.required(BitTableToolbarComponent);

  constructor() {
    this.tour.configure(
      [
        {
          id: "filters",
          anchor: computed(() => this.toolbar().filterButton()),
          position: "below-end",
        },
        {
          id: "filterRow",
          anchor: computed(() => this.toolbar().filterRow("vault")()),
          position: "above-center",
          beforeEnter: () => this.filterDialogOpen.set(true),
          afterLeave: () => this.filterDialogOpen.set(false),
        },
      ],
      { onEnd: () => this.saveTourCompleted() },
    );
  }
}
```

```html
<bit-table-toolbar [(filterDialogOpen)]="filterDialogOpen">…</bit-table-toolbar>

<bit-coachmark step="filters" [title]="…">…</bit-coachmark>
<bit-coachmark step="filterRow" [title]="…">…</bit-coachmark>
```

Call `tour.start()` when the user is eligible. The library doesn't store anything: persist
completion in `onEnd`, which runs whether the user finishes or dismisses the tour.

### Anchors

A step's `anchor` is an element, an `ElementRef`, or a signal of one: a `viewChild` for something
you render, or a `computed` over a ref a library component exposes (such as `bit-table-toolbar`'s
`filterButton`). The step waits for it to render and finish animating in, and hides while it's gone.

### Revealing a step's container

When a step's anchor lives inside something that has to be opened first — a dialog, a collapsed nav
group, another tab — open it in `beforeEnter` and close it in `afterLeave`. No delay is needed; the
step waits for its anchor.

### Conditional steps

A step with `when` is included only if it returns true when the tour starts. Skipped steps aren't
counted, so the indicator stays accurate.
