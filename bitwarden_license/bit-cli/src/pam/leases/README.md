# bw privileged-controls lease

Your privileged access leases: list, extend, end and reveal. Conventions are in
[`../README.md`](../README.md). Code lives here and in `bit-common/src/pam/leases/`.

| Command                                                                        | Needs             | SDK                                                                                          |
| ------------------------------------------------------------------------------ | ----------------- | -------------------------------------------------------------------------------------------- |
| `bw privileged-controls lease list [--active] [--names]`                       | `usePam`          | `leases().list_mine`                                                                         |
| `bw privileged-controls lease extend <leaseId> --duration <d> --reason <text>` | PAM seat          | `leases().list_mine`, `access_requests().cipher_access_state` (read-only), `leases().extend` |
| `bw privileged-controls lease end <leaseId> [--reason <text>] --yes`           | `usePam`, no seat | `leases().end`                                                                               |
| `bw privileged-controls lease reveal <cipherId> --field <field>`               | PAM seat          | `cipher_access_state`, `leases().leased_cipher`                                              |

- `list --active` drops lapsed leases with `isLeaseLive`, since nothing announces a lease running out.
- `extend` needs a non-empty reason (`--reason`, `--reasonfile` or `--reasonstdin`). It refuses a lapsed lease, a rule that disallows extensions (`extensionsAllowed`) and a `--duration` over `maxExtensionDurationSeconds`, before sending. A late extension resolves with status `denied` instead of throwing; that is reported as `The lease has ended` with a non-zero exit.
- `end` follows the destructive policy and needs `--yes`. A holder end settles to `canceled`; an approver or admin uses the same verb to revoke a live lease.
- `reveal` is the only command that prints decrypted data. `--field` is required (`password`, `username`, `totp`, `notes`, `uri`); there is no whole-item dump. It fails closed with `access not available` unless the lease is live, `leased_cipher` returns a view with `partial === false` and the same id. It writes the one field to stdout, never to a logger or stderr, and stores nothing. Missing-field wording follows `bw get`. `totp` prints the current code, generated by the CLI's `TotpService`; unlike `bw get totp` it does not check premium status.
- Mutating output carries only ids, states and timestamps.

## Serve

`GET /pam/lease?active=true`, `POST /pam/lease/:leaseId/extend` (`duration`, `reason` in the body) and `POST /pam/lease/:leaseId/end` (`"yes": true` in the body). `reveal` has no route.

## Open item

`leased_cipher` from the CLI device type is not live-verified yet (the server drops gated ciphers for non-web clients unless a lease is active). Treat `reveal` as unshipped until the Stage 6 live check passes.

`leases().list_active` is deliberately not used. Despite its SDK doc comment ("the caller's currently active leases"), the server answers it with the active leases on the collections the caller can manage, the approver view, so it is empty for an ordinary lease holder. `list --active` and `extend` read the caller's own leases from `list_mine` and keep those that are active with an open window.
