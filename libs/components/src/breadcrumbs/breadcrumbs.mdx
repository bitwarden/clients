## Usage

The breadcrumb component is used to indicate the user's current location in a hierarchical structure
of pages.

Breadcrumbs are typically paired with page content to help users understand where they are within a
site or application and navigate back to parent pages.

The active breadcrumb should always be the last in the list of breadcrumbs. (See
[Breadcrumbs with Page Header](#breadcrumbs-with-page-header) for the exception case.) Note that the
stories here in Storybook do not necessarily follow that guidance, in order to provide examples of
how the active styling works with the router.

### Routes

Breadcrumbs are typically links to page content. When provided a `route`, they will render as anchor
tag links. Without a `route`, the breadcrumb will be a button element and will need a `(click)`
handler attached.

Routed breadcrumbs hook into the Angular router to add styles the active breadcrumb and display it
as static text rather than a link. Button breadcrumbs will not display an active breadcrumb since
they are not hooked into the router.

### Start slot

A leading element can be projected into the `start` slot for a richer visual than the `icon` input —
most commonly a `bit-icon-tile`. When a `bit-icon-tile` is projected, its `size` is controlled by
the breadcrumbs `size`, so it stays in step with the crumbs without any extra wiring.

### Sizes

Size should be chosen based on available space. Use the base size on large screen layouts where
there is ample horizontal space. Use the sm size in space-constrained contexts, such as smaller
screen widths and the extension.

### Overflow

When a trail doesn't fit the available width, breadcrumbs collapse the middle: the first (root) and
last (current page) crumbs stay anchored, and the crumbs between them move into a "More" menu opened
by an <i class="bwi bwi-ellipsis-h"></i> button placed just after the root. Overflow is width-driven
— it responds to the container size rather than a fixed count — so the same breadcrumbs adapt across
layouts and screen sizes.

Collapsing works inward from the end of the trail, so **declare crumbs in path order, root first** —
the crumbs nearest the current page are the first to collapse. A crumb's contract is unchanged when
it collapses: same route or click handler, same label, now rendered as a menu item.

<Canvas of={stories.OverflowLinks} />

As space gets tighter, more middle crumbs collapse; at very small widths the root collapses into the
menu too, and finally the current page truncates. Drag the resizable container below to see it
adapt.

### Breadcrumbs with page header

Breadcrumbs projected into a [Header](?path=/docs/component-library-header--docs) through
`slot="breadcrumbs"` coordinate with it to determine which component renders the page's heading.
When one of the breadcrumbs matches the current route, that active breadcrumb renders as the page's
`<h1>` and the header suppresses its own title, so the page still has exactly one `<h1>`. The
coordination also relies on the two components sharing a `HeaderContext`, which a wrapper around
`bit-header` has to provide. See
[Page heading](?path=/docs/component-library-header--docs#page-heading) for the full behavior.

When breadcrumbs are used within a header that displays the active page outside of the breadcrumbs
(such as in a separate heading element), use `showTrailingArrow` to display one last arrow at the
end of the breadcrumbs list. This provides better visual continuity to guide the user's eyes to the
heading element as a logical continuation of the breadcrumbs. The heading element should be placed
immediately below the breadcrumbs.

Don't use `showTrailingArrow` when the last breadcrumb is the active breadcrumb.

## Accessibility

- The host carries `role="navigation"` with a localized `aria-label`, so assistive technology
  announces the trail as a landmark. Nothing extra is required of the consumer.
- Collapsed crumbs keep their semantics inside the menu — a crumb declared as a link is still a link
  there, so the full trail stays navigable at every width.
- The <i class="bwi bwi-ellipsis-h"></i> trigger has its own localized label and is only rendered
  when something has actually collapsed.

## Guidelines

Breadcrumb labels should reflect the exact page or section name for clarity and consistency.
