# Filter Menu

A composable family of filter chips for narrowing a list or table. A `bit-filter-menu` is a chip
trigger with a popover menu of options (optionally grouped by sections). A `bit-filter-toggle` is a
single on/off chip with no menu.

The chips work like a reactive form: each chip has a `key`, owns its own selection, and reports its
value up. The chips are **host-agnostic** — outside a table they just track their selection. Inside
a `bit-table-v2`, a chip registers itself automatically and its value lands in
`table.filterValues()` — see
[Table V2 › Filtering](?path=/docs/component-library-table-v2-beta--docs).

## Composition

A chip is single-select by default; add `multiple` for a checkbox-style multi-select.

```html
<bit-filter-menu key="type" placeholderText="Type" unsetLabel="All">
  <bit-filter-option [value]="'login'" [count]="12">Login</bit-filter-option>
  <bit-filter-option [value]="'card'" [count]="3">Card</bit-filter-option>
</bit-filter-menu>

<bit-filter-menu key="vault" placeholderText="Vault" multiple>
  <bit-filter-option [value]="'mine'" [count]="20">My vault</bit-filter-option>
  <bit-filter-option [value]="'acme'" [count]="11">Acme corporation</bit-filter-option>
</bit-filter-menu>
```

| Component            | Purpose                                                                                                     |
| -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `bit-filter-menu`    | Chip trigger + popover; owns the selection (`multiple` for multi).                                          |
| `bit-filter-toggle`  | Single on/off chip (no menu); boolean value; `iconActive` swaps the icon while active.                      |
| `bit-filter-option`  | A selectable row with a radio/checkbox indicator; shows a count in a table (or an explicit `count`). Nests. |
| `bit-filter-section` | A labelled, optionally collapsible group of options; shows a count berry of its selected options.           |
| `bit-filter-divider` | A vertical rule for separating groups of chips in the chip row.                                             |

## Nesting

Project `bit-filter-option`s inside one another to make an expandable parent — a collection and the
collections beneath it, say. Selecting a parent selects everything under it and clearing it clears
the same set, so a parent acts as a bulk control rather than a value that can drift out of step with
its children. A parent whose subtree is only partly selected renders indeterminate, and that
propagates up through every level.

```html
<bit-filter-menu key="collection" placeholderText="Collections" multiple>
  <bit-filter-option [value]="'eng'" [count]="15" expanded>
    Engineering
    <bit-filter-option [value]="'monitoring'" [count]="20">Monitoring</bit-filter-option>
    <bit-filter-option [value]="'infra'" [count]="6">
      Infrastructure
      <bit-filter-option [value]="'cicd'" [count]="2">CI/CD</bit-filter-option>
    </bit-filter-option>
  </bit-filter-option>
</bit-filter-menu>
```

Parents start collapsed; add `expanded` to start one open.

<Canvas of={stories.NestedOptions} />

Write the nesting out in markup — literally, or with an inline `@for` per level. Angular resolves
both content projection and content queries against where a template is _declared_, so recursing
through `ngTemplateOutlet` doesn't work: the child options are neither projected past the parent's
label nor visible to its content query. Depth is therefore whatever the template spells out.

## Keyboard

A single-select menu is a group of radios: the browser gives it one tab stop, arrow keys move and
select, and Space selects.

A multi-select menu is a **tree** — rows are selectable, rows can own rows, and a parent can be
partly selected, which is more than a listbox can express. It's one tab stop, navigated with:

| Key            | Behaviour                                          |
| -------------- | -------------------------------------------------- |
| `↑` / `↓`      | Move between the rows currently on screen          |
| `→`            | Open a closed row; step into an already-open one   |
| `←`            | Close an open row; otherwise move up to the parent |
| `Home` / `End` | First / last row                                   |
| `Space`        | Select or clear the row, and everything beneath it |

The expander is driven by `←`/`→` rather than being its own tab stop, and section headers are rows
too — expandable but not selectable. Typeahead is not enabled; use the search field to narrow a long
list.

Navigation is CDK's `TreeKeyManager`; each row adapts itself to its item contract via
`bitFilterTreeRow`. The row is the item rather than the `bit-filter-option` behind it, because an
option is declared once but rendered per surface, so only the row maps one-to-one onto something
focusable.

Both surfaces sit in a `dialog`-role popover, so `Tab` reaches the search field and the footer
instead of dismissing, and `Escape` closes and returns focus to the chip. Opening puts focus
straight on the first row — or the search field, when there is one — rather than on the popover
itself, so the arrow keys work without a priming `Tab`.

## Value

A chip is a named form control. It owns its selection — **no `ngModel`** — and exposes it under its
`key`: a single value for single-select, an array for `multiple`. Options may be grouped into
`bit-filter-section`s for display; they all feed the chip's one selection.

The chip builds its label from the selected options (`placeholderText`, or
`placeholderText: unsetLabel` while empty). While active it shows a clear (`x`) on the chip; a
`multiple` chip also gets a sticky **Clear** button pinned to the bottom of its menu. Both reset the
selection.

## Icon tiles

An option can render a leading `bit-icon-tile` — pass an `iconTile` config and the chip draws it at
`size="xs"` so every row lines up.

```html
<bit-filter-menu key="type" placeholderText="Type" multiple>
  <bit-filter-option [value]="'login'" [iconTile]="{ icon: 'bwi-globe', variant: 'brand' }">
    Login
  </bit-filter-option>
</bit-filter-menu>
```

Usage guidelines:

- Use a tile on every option in a chip, or on none of them — a partial set leaves the labels ragged.
  On a single-select chip, remember the auto-injected "All" row has no tile.
- The tile is decorative; the option label carries the meaning, so no `ariaLabel` is applied.
- A disabled option's tile renders in the neutral `gray` family and ignores any custom `color`, so
  it reads as inactive alongside the muted label.

## In-menu search

Once a chip has more than ten options it renders a `bit-search` at the top of its own menu — you
never project a search field. It narrows the chip's options by their label: non-matching options
hide, a `bit-filter-section` collapses when all of its options are hidden, and a "no matching items"
message shows when nothing matches. The term resets when the menu closes.

A parent option stays visible while anything beneath it matches, and its children are forced open
for the duration of the search — so a nested match is reachable through its ancestors instead of
being hidden along with them.

## Driving a table

Project a chip into a `bit-table-v2` and it registers itself. The chip's value lands in
`table.filterValues()` under its `key`; the table's `filter(row, values)` reads it. There are no
matchers and no per-chip state — see
[Table V2 › Filtering](?path=/docs/component-library-table-v2-beta--docs).

```html
<bit-filter-menu key="type" placeholderText="Type" unsetLabel="All">
  <bit-filter-option [value]="'login'">Login</bit-filter-option>
</bit-filter-menu>
```
