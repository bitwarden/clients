# Menu

The menu component is used to present a list of actions, selections, or navigation options in a
floating overlay. It appears in response to a user interaction, like a button or trigger, and
provides contextual choices relevant to the current workflow.

## Composition

A menu is constructed of a `bit-menu` element with child `bitMenuItem` elements. These can be
anchors or buttons. Items placed in `slot="footer"` are sectioned off below a divider rule; use
`bit-menu-divider` to section the list itself, which also allows more than one break.

Menu triggers use the `bitMenuTriggerFor` directive to specify the menu they open.

Example code:

```html
<button type="button" bitButton buttonType="secondary" [bitMenuTriggerFor]="myMenu">
  Open menu
</button>

<bit-menu #myMenu>
  <a href="#" bitMenuItem>Anchor link</a>
  <bit-menu-divider></bit-menu-divider>
  <button type="button" bitMenuItem>Button</button>
  <button type="button" bitMenuItem slot="footer">Footer button</button>
</bit-menu>
```

### Context menus

`bitContextMenuTriggerFor` opens the same `bit-menu` on right-click, anchored at the cursor. Use it
when the menu belongs to a whole region — a table row, a card — rather than to a single button.

```html
<div tabindex="0" [bitContextMenuTriggerFor]="myMenu">Right-click me</div>
```

Usage guidelines:

- Give the host a `tabindex`. Right-click alone is not a keyboard-accessible affordance, so the
  directive also opens on `Shift+F10` and the `ContextMenu` key — both of which require the host to
  be focusable. It's also how focus returns to the host when the menu closes.
- Right-clicking again while the menu is open moves it to the new cursor position.
- `Shift+Ctrl` and right-click is left alone as an escape hatch to the browser's own menu.
- A context menu is an addition, not a replacement. Anything reachable only by right-click is
  undiscoverable, so pair it with a visible trigger — the two directives can point at the same
  `bit-menu`.

### Menu Items

`bitMenuItem` supports the following slots:

| Slot           | Description                                         |
| -------------- | --------------------------------------------------- |
| default        | primary text or arbitrary content                   |
| `slot="start"` | commonly an icon or avatar; before the default slot |
| `slot="end"`   | commonly an icon; after the default slot            |

```html
<button type="button" bitMenuItem>
  <bit-icon class="bwi-key" slot="start" />
  Menu item with icons
  <bit-icon class="bwi-angle-right" slot="end" />
</button>
```

#### Icon tiles

`slot="start"` also accepts a `bit-icon-tile` when the leading visual should carry a color to
distinguish categories of items.

```html
<button type="button" bitMenuItem>
  <bit-icon-tile icon="bwi-globe" variant="brand" size="xs" slot="start" />
  Menu item with an icon tile
</button>
```

Usage guidelines:

- Always use `size="xs"`, so menu items and select options share the same leading-visual footprint.
- Use a tile for every item in the menu, or for none of them.
- Leave `ariaLabel` unset. The tile is decorative — the menu item text carries the meaning.

### Action menus

Action menus are used used for contextual actions such as edit, delete, copy, and similar
operations.

Usage guidelines:

- Use the menu item `danger` variant for destructive operations.
- If using leading icons, all menu items must have a leading icon; otherwise, no menu items should
  have a leading icon.
- Menu items should be anchors or buttons, depending on the action they execute.

## Accessibility

`bitMenuTriggerFor` uses the `aria-haspopup` and `aria-expanded` attributes to provide an accessible
implementation. `bit-menu` specifies a `role` and accepts an optional `aria-label` for menus that
need a differentiating accessible name. `bitMenuItem` also specifies an accessible role for itself.

Users are able to navigate the opened menu via the up and down arrow keys and close the menu using
the escape key or clicking out of the menu.

`bitContextMenuTriggerFor` opens on `Shift+F10` or the `ContextMenu` key, so the menu is reachable
without a pointer. That only works if the host is focusable — see the context menu guidelines above.
It sets `aria-haspopup` but not `aria-expanded`: its host is an arbitrary region with no role, and
`aria-expanded` is not a global attribute, so binding it there would be invalid ARIA.
