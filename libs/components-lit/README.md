# @bitwarden/components-lit

Bitwarden design system components built as framework-neutral web components with [Lit](https://lit.dev). Feature parity target: `libs/components`.

```sh
npm run storybook   # from this directory, serves on :6008
```

Host pages must load `src/styles/document.css` (theme variables, fonts, icon font face) and may call `setTranslator()` and `setAsyncActionErrorHandler()` once at startup.

## Conventions

### Files

- One folder per component family: `src/<name>/<name>.ts`, `<name>.stories.ts`, `index.ts`.
- Tag `bit-<name>`, class `Bit<Name>`, registered with `@customElement` and added to `HTMLElementTagNameMap`.
- Helper elements not meant for consumers are marked `@internal` and not exported from `index.ts`.

### Styling

- Extend `BitElement`; add component CSS with `static styles = [BitElement.styles, css\`...\`]`.
- Use `tw-` Tailwind classes in templates as in `libs/components`. Class strings must be full literals (map values to complete class strings); the shared sheet is generated by scanning this library's source.
- Consumers' Tailwind classes don't reach inside a shadow root. Expose layout knobs as CSS custom properties or `::part()`s, not class-name inputs.
- Document styles beat `:host` rules (outer cascade context wins), and the document preflight resets borders on every element. Put borders/backgrounds on an inner element rather than `:host`.
- `bit-compact:` works via the inherited `--bit-compact` custom property (set by `.bit-compact` in the document).

### API

- Mirror the Angular API names where they still make sense (`buttonType`, `startIcon`, `variant`, ...). Multi-word properties use kebab-case attributes (`button-type`).
- Booleans default to `false`. Variants are string-literal unions.
- `ng-content` becomes `<slot>`; `select="[slot=end]"` becomes `<slot name="end">`.
- Angular outputs become `CustomEvent`s with the same name (`dismissed`, `selectedChange`), `bubbles: true, composed: true`.
- Angular DI between parent and child becomes [`@lit/context`](https://lit.dev/docs/data/context/) providers and consumers. Use `Symbol` keys, and `subscribe: true` on consumers that must react to changes. `src/core/context-root.ts` replays requests made before a provider upgrades.
- Attribute directives (`bitTooltip`, `bitMenuTriggerFor`, ...) become a framework-neutral `attachX(element, options)` function returning a handle, plus a Lit element directive and, where useful for plain HTML, a wrapper element. See `src/tooltip/`.
- Angular services (`DialogService`, `ToastService`) become plain module functions (`openDialog()`, `showToast()`).
- Router inputs (`route`) become `href` plus an explicit `active`/`current` property.
- `bitAction` / `bitSubmit` become `action` properties taking promise-returning functions (`src/core/async-action.ts`).
- Form controls extend `BitFormControlElement` (`src/core/form-control.ts`) and use `Validators` (`src/core/validators.ts`). Labels, hints and errors render inside the control so ARIA references stay within one shadow root.

### Accessibility

- Components whose interactive element lives in their shadow root implement `AriaTargetHost` so behaviors can set ARIA state on it.
- Use `ElementInternals` (`role`, `aria*`) for host semantics and element reflection (`ariaDescribedByElements`, ...) for references that must cross into an ancestor tree.
- Overlays use the `popover` attribute or `<dialog>` for top-layer rendering, `computePosition`/`autoUpdate` for placement, and `trapFocus`/`captureFocus` for focus management. Lists use `KeyManager`.

- Keep side-effect element imports (`import "./x"`) separate from `import type { X } from "./x"`. `eslint --fix` merges them otherwise, and a type-only import is elided, so the element never registers.

### Stories

- Title `Component Library/<Name>`, matching `libs/components`. Cover every state the Angular stories cover.
- Prefer stories over unit tests; reserve tests for non-rendering logic.
